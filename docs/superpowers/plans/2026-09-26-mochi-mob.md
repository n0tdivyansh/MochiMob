# Mochi Mob Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build *Mochi Mob*, an original browser co-op puzzle platformer (solo, local 2–4, online rooms) with 20 levels, clay-blob visuals and procedural audio.

**Architecture:** A pure, deterministic simulation module (`src/sim`) owns every game rule and runs identically in the browser (solo/local/prediction) and in a Node WebSocket server (online authority). Rendering (Canvas 2D), audio (WebAudio), input and HTML UI are thin layers that read sim state and events. Levels are data; a closed-loop bot drives headless solution replays that prove every level is solvable.

**Tech Stack:** Node 20+, Vite 6, vanilla ES modules, Canvas 2D, WebAudio, `ws` 8, Vitest 2, `concurrently` for dev.

**Spec:** `docs/superpowers/specs/2026-09-26-mochi-mob-design.md`

## Global Constraints

- Project root: `games-clone/mochi-mob/`, its own `package.json`, `"type": "module"`.
- Virtual resolution 1920×1080; tile 64 px; fixed step 1/60 s (`DT = 1/60`).
- `src/sim/**` must not use DOM, `window`, `Date`, `performance`, timers or `Math.random`.
- All sim state is plain JSON-serializable data (numbers, strings, booleans, arrays, plain objects).
- Player palettes (index order): Strawberry `#ff7aa2` heart, Matcha `#7fcf6a` leaf, Yuzu `#ffd24d` star, Ube `#a68bff` moon.
- Input bits: `LEFT=1, RIGHT=2, JUMP=4, SQUISH=8, UP=16`.
- 2–4 players/blobs everywhere; minimum 2.
- No copied assets: every sprite, sound and melody is generated in code.
- Solo + local co-op work from a static `dist/` with no server. Online server URL from `VITE_SERVER_URL`, else same origin `/ws`.
- Dev ports: Vite 5175, server 8787. Production: single port from `PORT` (default 8787).
- Commits are local only (`git init` inside `mochi-mob/`); never push.
- Spec deviation (deliberate): squished hitbox is 52×24 (same width as normal) instead of 60×24, so squishing never widens into walls.

## Review Focus

1. **Blob stacks under motion** — a tower of blobs on a moving lift or pushed crate must stay stacked without jitter, sinking or tunnelling. Test: Task 5 `tower on lift stays stacked 600 ticks`.
2. **Respawn into occupied space** — a blob respawning where teammates or a crate stand must not spawn inside them. Test: Task 7 `respawn stacks above occupant`.
3. **Crate falls in pit** — a lost crate would soft-lock the level; it must return home. Test: Task 6 `crate below level returns home`.
4. **Gate closing on a blob** — gate must not crush or trap a body in its path. Test: Task 6 `gate does not close onto body`.
5. **Online client sends garbage / floods** — malformed JSON, wrong types, oversize, >120 msg/s must not crash the server or affect other rooms. Tests: Task 21 validation suite, Task 22 `flood disconnect`.

### Task 4: Blob control and step skeleton

**Files:** Create `src/sim/blob.js`, `src/sim/step.js`; Test `tests/sim/blob.test.js`

**Interfaces — Produces:** `step(state, inputs)` with tick order:
1. `state.events = []`; `pressed = bits & ~prev` per blob.
2. `updateObjects(state)` (plates → gates/lifts targets; Tasks 5–6).
3. `controlBlob(state, blob, bits, pressed)` for alive, not-inDoor blobs: accel/friction (none while squished), facing, coyote/buffer, jump (`vy=-JUMP_V`, event `jump`), cut (once, not when `bounced`), squish enter (grounded + SQUISH) / leave (needs 24 px head room), gravity, clamp.
4. `integrate(state)`: lifts move; dynamic bodies sorted by bottom desc (ties by index); carry `dx += support.mx (+ conveyor ±CONVEYOR*DT)`, `dy += max(0, support.my)`; `moveY` then `moveX`; horizontal block by an unmoved dynamic body → defer to pass 2. Horizontal hit by moving dynamic body: `vx = sign(vx)*min(|vx|, |hit.mx|/DT)`, else `vx=0`. Upward motion pushes riders via recursive `pushUp`.
5. Landing: `land` event when landing with previous `vy>300`; landing on squished blob → `vy=-BOUNCE_V, bounced=true`, event `bounce`; landing on pad tile → `vy=-PAD_V`, event `pad`.
6. Hazards/key/door/checkpoints/paint (Task 7), tether (Task 9), `tick++`, `prev=bits`.
